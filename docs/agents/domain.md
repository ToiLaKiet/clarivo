# Domain docs

This is a single-context repository.

Before working in a domain area, read the root `GLOSSARY.md` and relevant
ADRs in `docs/adr/` if they exist. Proceed silently when they do not exist;
create domain docs only when terms or decisions are actually resolved.

Use glossary terms consistently in tickets, code, and tests. If proposed
work conflicts with an ADR, identify the conflict instead of silently
overriding the decision.
