CLARVIO / Database design

Workspace data, from request to approved plan

The first view shows tables that exist today. The second shows the relationships planned for document intake, clarification, task planning, assignment, and approval.

Current SQLite schema

Migration 0001_workspace_versions.sql creates the first three tables; the store bootstraps schema_migrations. Only plan_versions.workspace_id is a database foreign key.

A save inserts a new plan version and advances workspaces.current_version in one transaction. PK chips on two rows form a composite key. The pointer and idempotency scope are enforced by application logic; additional CHECK rules live in the SQL migration.

Planned logical model

Only Workspace and Plan version are implemented so far. Other boxes describe domain records from ADR 0001, not existing SQL tables or finalized columns.

Evidence links from Requirements to Sources or Messages, Task dependencies, and employee workload inputs are described in the ADR. Their join tables and keys will be designed in later migrations.
